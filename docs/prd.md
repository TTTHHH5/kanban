# PRD — Product Requirements Document
# Kanban Board

## 1. 개요

| 항목 | 내용 |
|------|------|
| 제품명 | Kanban Board |
| 버전 | 1.1 |
| 작성일 | 2026-05-13 |
| 작성자 | TTTHHH5 |

### 배경
팀 또는 개인의 작업 흐름을 시각화하고 태스크 상태를 직관적으로 관리할 수 있는 칸반 보드가 필요하다.
**현재는 단일 브라우저 환경**에서 동작하지만, 향후 Supabase 기반 인증을 붙여 **복수 사용자가 각자의 보드를 독립적으로 사용**할 수 있도록 확장할 계획이다.
이에 따라 현재 구현에서도 사용자 식별 구조를 미리 갖춰 두어, 인증 도입 시 최소한의 수정으로 전환할 수 있어야 한다.

### 목표
- 작업 항목(카드)을 To Do / In Progress / Done 세 단계로 분류·관리한다.
- 드래그앤드롭으로 카드를 컬럼 간 이동시켜 상태를 변경한다.
- 데이터는 사용자 단위로 격리·저장되어 새로고침 후에도 유지된다.
- 인증 레이어(Supabase)를 추가할 때 기존 데이터 구조를 그대로 재사용할 수 있다.

| 팀원 | 같은 조직의 보드를 함께 열람·관리하는 사람 | 🔜 v3.0 |

## 3. 기능 요구사항

### 3.1 보드 (Board)
| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| F-01 | 보드는 To Do, In Progress, Done 3개 컬럼을 수평으로 표시한다 | Must |
| F-02 | 각 컬럼 헤더에 해당 컬럼의 카드 수를 실시간으로 표시한다 | Must |

### 3.2 카드 (Card)
| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| F-03 | 카드는 텍스트 내용을 가진다 | Must |
| F-04 | 카드를 드래그해 다른 컬럼으로 이동할 수 있다 | Must |
| F-05 | 카드를 드래그해 같은 컬럼 내 순서를 변경할 수 있다 | Must |
| F-06 | 드래그 중 삽입 위치를 점선 placeholder로 표시한다 | Must |
| F-07 | 드래그 중 대상 컬럼이 하이라이트된다 | Should |
| F-08 | 카드에 hover 시 삭제 버튼(✕)이 나타난다 | Must |
| F-09 | 삭제 버튼 클릭 시 해당 카드가 제거된다 | Must |

### 3.3 카드 추가
| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| F-10 | 각 컬럼 하단의 "+ 카드 추가" 버튼으로 모달을 열 수 있다 | Must |
| F-11 | 모달에서 텍스트 입력 후 확인(버튼 또는 Enter)으로 카드를 추가한다 | Must |
| F-12 | 빈 텍스트로는 카드를 추가할 수 없다 | Must |
| F-13 | Esc 또는 오버레이 클릭으로 모달을 닫는다 | Must |

### 3.4 사용자 식별 및 데이터 격리
| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| F-14 | 앱은 현재 사용자를 식별하는 `currentUser` 상태를 가진다 | Must |
| F-15 | 로그인 전에는 브라우저 고유의 게스트 ID를 자동 발급한다 | Must |
| F-16 | 카드 데이터는 사용자 ID를 키로 하여 격리 저장된다 | Must |
| F-17 | 카드 추가/삭제/이동 시 변경 사항이 저장된다 | Must |
| F-18 | 페이지 새로고침 후 현재 사용자의 마지막 상태가 복원된다 | Must |

### 3.5 인증 (v2.0 — 미래 요구사항)
| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| F-19 | 사용자는 Supabase Auth를 통해 이메일/소셜 로그인을 할 수 있다 | 🔜 Should |
| F-20 | 로그인 시 게스트 데이터를 인증 계정으로 마이그레이션할 수 있다 | 🔜 Could |
| F-21 | 헤더에 로그인 상태(아바타, 이름)를 표시한다 | 🔜 Should |
| F-22 | 로그아웃 시 해당 사용자 세션이 초기화된다 | 🔜 Should |

## 4. 비기능 요구사항

| ID | 요구사항 |
|----|----------|
| NF-01 | 현재 구현은 외부 라이브러리 없이 순수 HTML/CSS/JS로 동작한다 |
| NF-02 | 모던 브라우저(Chrome, Firefox, Safari 최신 2버전)를 지원한다 |
| NF-03 | 드래그앤드롭 인터랙션 응답 시간은 사용자가 지연을 인식하지 못하는 수준이어야 한다 |
| NF-04 | 스토리지 레이어는 localStorage와 Supabase를 교체 가능한 구조로 추상화한다 |
| NF-05 | 카드 데이터는 반드시 사용자 ID를 포함하여 저장한다 (다중 사용자 전환 시 격리 보장) |
